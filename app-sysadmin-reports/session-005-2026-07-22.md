# Session 5 — `admin.wagrab.com` 502 Traced to Node 22→24 ABI Break in `isolated-vm`; Pinned `wagrab-admin`/`feyfa-admin` to Node 22

**Date:** 2026-07-22
**Server:** `root@app` / `devops@app` (`154.26.129.104`, internal `10.0.0.5`) — fix also touched `root@proxy` (nginx)
**OS:** Ubuntu 24.04.4 LTS
**Goal:** `admin.wagrab.com` returning 502. Find root cause, fix.

---

## TL;DR

`wagrab-admin` (Directus CMS, PM2 id 33) was reported as **502 Bad Gateway**. PM2 showed it "online" with 0 restarts — but the process had **no listening socket at all**: a zombie that never finished booting.

Root cause: [ytgrab session-022](../ytgrab-app-reports/session-022-2026-07-22.md) upgraded Node to **24 fleet-wide** on `app` via `apt install nodejs` (NodeSource), which — per that session's own risk note — triggered a `needrestart`-driven bounce of **every** PM2 process on the box, not just the ytgrab ones it targeted. `wagrab-admin` got swept up in that bounce and came back under Node 24. Its bundled native module `isolated-vm` (Directus's Flows/"Run Script" sandbox engine) was compiled for Node 22 (`NODE_MODULE_VERSION 127`) and fails to load under Node 24 (`NODE_MODULE_VERSION 137`) — `ERR_DLOPEN_FAILED`. That error hangs Directus's extension bootstrap before it ever calls `app.listen()`, leaving a process that's alive (sleeping, 0% CPU, no restarts) but deaf to all traffic.

A rebuild attempt (`npm rebuild isolated-vm`) failed harder than expected: this version of `isolated-vm` doesn't just need recompiling, it **cannot compile at all** against Node 24's V8 headers (`error: "C++20 or later required"`, V8 API shape changes). Directus 11.15.4 was never built/tested for Node 24.

**Fix:** installed `nvm` + Node 22.22.0 on `app` (matching the pre-upgrade system version) and pinned `wagrab-admin` to it via `pm2 restart wagrab-admin --interpreter <node22-path>`. Verified `admin.wagrab.com` → 200, `/server/ping` → `pong`.

**Blast radius check:** scanned every app's rotated error log for the same `ERR_DLOPEN_FAILED`/`NODE_MODULE_VERSION` signature. Only one other app matched — **`feyfa-admin`** (also Directus + `isolated-vm`, older version 11.4.1). Same fix applied: pinned to the same Node 22.22.0 binary, verified listening + serving (`Loaded extensions`, `Server started at http://10.0.0.5:8002`). No other PM2 app on the box showed this error.

**Separately (user-flagged, unrelated to the Node issue):** `feyfa-admin`'s public domain (`admin.foucher.co` / `api.foucher.co`, proxied via `/etc/nginx/sites-available/foucher-admin.conf` → `10.0.0.5:8002`) needs to be renewed by the user. Disabled the nginx site (removed `sites-enabled` symlink, config preserved in `sites-available`, `nginx -t && systemctl reload nginx`) so it's cleanly paused rather than serving through an expiring domain.

## Cumulative Node-Version Note

`app` now runs a **mixed Node fleet**: system default Node 24 (NodeSource, no nvm) for most PM2 apps, with `wagrab-admin` and `feyfa-admin` explicitly pinned to Node 22.22.0 via `nvm` + PM2 `--interpreter` because of a native-module incompatibility. Any future PM2 restart of these two **must** keep the `--interpreter` flag (or persist it via `pm2 save`) — a plain `pm2 restart` without it would fall back to bare `node` on PATH (Node 24) and reintroduce this exact outage.
