## Why code had to change first

Session-001 identified 5 blockers. All were fixed and shipped before any wiring:

| # | Bug | Impact if wired as-is | Fix |
| --- | --- | --- | --- |
| 1 | `resolvePromoLink` mapped `svc_bwalk`/`svc_technopark` to `*.dev.hoteru.uk`, and guessed a `.dev` host for unmapped services | Affiliates copy promo links from the portal and post them publicly → **real referral traffic to staging sites** | Mapped to live hosts; unmapped services fall back to Hoteru's documented `<hotel>.hoteru.co.id` convention; test asserts no link ever contains `.dev.` |
| 2 | `syncPartnerAffiliate` wrote the partner-reported rate onto demo offer `offer_room_weekend_001`, which no real event matches, so JIT fell back to a flat 1000 bps | **Technopark's 9 affiliates at 1% and one at 0% would all have accrued at 10%** in the shadow ledger | Rate now lands on a `__default__` sentinel row that JIT copies (capped at master); a re-sync updates it (`db/affiliate-rate-defaults.ts`) |
| 3 | Hoteru's `emit()`/`syncAffiliate()` ignored the HTTP response | Avilia rejects with **non-2xx, not an exception** → a bad secret / unprovisioned service looked identical to "no affiliate bookings yet" | `logIfRejected` logs status + body at both call sites, still non-throwing |
| 4 | `defaultRateBps: rateBps > 0 ? rateBps : 1000` treated a genuine 0% as missing | Technopark's 0% affiliate would be silently promoted to 10% | Only a non-finite/negative rate falls back |
| 5 | 3 stale integration tests asserted pre-change behaviour | Masked real regressions | Updated to the current contract + new JIT/rate-inheritance coverage |

`aff123` (the shared default password every synced affiliate gets) was **kept by explicit
decision** — Avilia has no email delivery, so randomising it would lock out all 117 affiliates with
no way to send credentials. Affiliates can change it via `/api/auth/change-password`. Tracked as an
open follow-up; it is the single biggest remaining risk in this integration.

### Wiring detail

```env
AVILIA_ENABLED=true
AVILIA_EVENTS_URL=http://10.0.0.5:3140/api/service-events/events   # PRIVATE, not api.avilia.id
AVILIA_SERVICE_ID=svc_bwalk | svc_technopark
AVILIA_SERVICE_SECRET=<64-char, generated by Avilia at provisioning>
```

The **private** URL is deliberate: both apps run on `app`, so events skip the Cloudflare hairpin
(whose WAF/bot rules can block server-to-server POSTs) and never leave the host. Payloads are
HMAC-signed regardless, so nothing is weakened.

## Incident — portal 403 for ~90s (self-inflicted, resolved)

While deploying the portal bundle I piped a remote `tar` through an SSH call that **also** printed
PM2/curl output, so the archive was corrupted by that text. The remote command had already run
`rm -rf /var/www/avilia-app/*` before `tar` failed, leaving the directory empty — `app.avilia.id`
served **403 for roughly 90 seconds**.

Restored immediately from the `cp -a` backup taken seconds earlier in the same command, then
redeployed correctly. **Root cause:** mixing a binary stream with human-readable output in one SSH
invocation, plus deleting before verifying the replacement. **Fix applied:** the tar stream now runs
in its own SSH call, the archive is validated (`tar tzf`) locally, extracted to `/tmp` on the proxy,
checked for `index.html`, and only then `rsync --delete`d into place — never delete-then-extract.
The API was never affected; `api.avilia.id` stayed 200 throughout.

## Findings

- **Rate model divergence is now real and intentional.** Avilia computes master 1500 bps and pays
  the affiliate their Hoteru rate; the spread is platform margin. For Technopark's 1% affiliates
  that implies a **14% platform margin**, which is only correct if Technopark actually agreed to pay
  15%. Flagged for business confirmation — the number was chosen as the pilot default, not from a
  signed agreement.
- **Hoteru remains the system of record.** `CommissionService` is untouched and still authoritative;
  Avilia is a shadow ledger. No payout authority moved.
- **`syncAffiliate` fires only on affiliate creation**, so the backfill was a one-off. Rate *changes*
  made in Hoteru after today will **not** propagate to Avilia — there is no update hook. Re-running
  the backfill is the current remedy (it is idempotent and updates the `__default__` row).
- No email collisions: all 117 affiliate emails are unique within and across both hotels, so no
  cross-tenant user was silently merged.
