**Found + fixed a second live nginx footgun while applying the snippet.** The app repo's canonical
file sets `proxy_set_header X-Forwarded-Proto $scheme;` on every block — but the hand-maintained
prod vhost has an existing, deliberate, documented rule that `eventopia_web` (Next standalone)
EPROTO-self-rewrites on that exact header at the apex (see the "www + wildcard tenant" server in
the same file). Pasting the snippet verbatim would have reintroduced that bug for every capability
path. Backed up `eventopia.conf`, applied the snippet's location list **adapted** — same paths,
same upstream, this proxy's own existing header conventions (kept `proxy_http_version`/`Upgrade`/
`Connection`/`proxy_read_timeout`, omitted `X-Forwarded-Proto`) — added the 4 new pre-emptive
blocks, `nginx -t` clean, reloaded. Documented the adaptation back in the app repo
(`infra/nginx/eventopia-apex-capability-paths.conf`, commit `6f340d7f`, local-only) so a future
verbatim copy doesn't reintroduce it.
