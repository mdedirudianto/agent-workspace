## Deploy

1. **Backup:** `pg_dump -Fc` on `app` via its own `DATABASE_URL` → `~/db-backups/eventopia-prod-pre-va-bank-v3-fallback-20260723.dump` (468KB), following the existing `app:~/db-backups/` convention (session-032's).
2. **Code:** `git pull` — clean fast-forward `fc32f4f1`→`66c1a329`. `pnpm install --frozen-lockfile` (lockfile unchanged, no new deps).
3. **Migration — hit a new gotcha:** `pnpm --filter @eventopia/db db:migrate` (the exact command the last several deploy notes use) failed outright, `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL`, with **drizzle-kit's CLI swallowing the real error** behind its spinner (only a generic exit-1, no stack trace, even with ANSI stripped). Nothing applied — verified via `information_schema` that neither new column existed, so the failure was clean (no partial DDL). Root-caused by falling back to the same **direct `drizzle-orm` migrator script** technique sessions 009's `node --env-file` workaround and 032/033's manual-DDL sessions established: found `run-migrate.mjs` already sitting untracked on `app` from a prior session, fixed its relative `migrationsFolder` path for the copy run from `packages/db/`, and it applied both migrations cleanly on the first real attempt (only benign "schema already exists" NOTICEs). This is the same family of `drizzle-kit migrate` CLI-vs-driver flakiness session-009 hit ("silent-failure gotcha") — worth a `MIGRATIONS.md` note if it recurs a third time. Verified after: `__drizzle_migrations` count 106→108, `disabled_va_banks` (jsonb, nullable) and `bank_code` (text, NOT NULL, default `''`) both present, `organizer_payment_method_status_key_uq` correctly widened to `(organizer_id, provider, method, bank_code, collection_mode)`.
4. **Build + restart:** `pnpm --filter @eventopia/console build` (0.30.0) and `pnpm --filter @eventopia/web-public build` (0.21.0) both clean. `pm2 restart ecosystem.config.cjs --only eventopia-api,eventopia-workers,eventopia-console,eventopia-web-public --update-env` (ecosystem-file form from the start, avoiding session-028's `--update-env`-alone gotcha). `eventopia-operator`/`eventopia-checkin` untouched (nothing in the diff touches them).
