## Report

User asked why the organizer's checkout-leads follow-up feature (event follow-up campaigns,
shipped session-057, templates approved session-058) seems to surface "only a few" people to
message on **Festival Mbois 11 - Concert**, and specifically that it "doesn't capture new
lead/expired payment that can be broadcasted."

### The event(s)

The organizer has two live listings for what appears to be the same concert (a pre-existing
condition, not something this session touched):

| Event | id | Status |
|---|---|---|
| Festival Mbois 11 - Concert | `evt_06965c30-bf9b-45b4-b146-110c93bce5f3` | PUBLISHED |
| Festival Mbois 11 - Concert by BRImo | `evt_0e2a87c1-63cc-4054-a15a-a84ab221af76` | PUBLISHED |

### What's actually in the database (Festival Mbois 11 - Concert)

```
orders:          EXPIRED 220 · PAID 180 · PENDING 1
checkout_lead:    ABANDONED 1258 · CONVERTED 73 · OPEN 16
```

Of the 1,274 OPEN+ABANDONED `checkout_lead` rows, only **53** are actually eligible for the
leads list / a broadcast (`listableCheckoutLeadCore`: status OPEN/ABANDONED, no linked order,
has a phone or email) — 1,159 are pre-identity anonymous carts (no phone/email, correctly
excluded, funnel signal only) and 81 already have a real order and are correctly superseded by
it. 45 of those 53 carry `consent_marketing = true`.

### What a campaign can actually reach today

The composer (`apps/console/.../broadcast/new/page.tsx`) offers two audiences, both computed in
`apps/api/src/modules/events-broadcast/repo.ts`:

- **"Abandoned checkouts"** (`EVENT_LEADS`) reads `checkout_lead` only → **53 candidates**
  before phone-dedupe/consent (`45` consented).
- **"Unpaid orders"** (`EVENT_UNPAID_ORDERS`) reads `orders` where `status='PENDING'` and still
  inside its expiry window → **1 candidate** (the single live PENDING order right now).

**Neither audience includes the 220 EXPIRED orders.** Those are real buyers who reached the
payment step, submitted a real cart, and let the payment session lapse — the highest-intent
segment on the list, 219 of 220 with a usable phone number, arriving continuously (26 on
2026-08-10 alone, 2 already today) — and they are invisible to both broadcast audiences. They
only appear one at a time on the organizer's **Leads** page, where a human has to open a `wa.me`
link per person.

The second listing, "…by BRImo," has the same shape: 296 EXPIRED orders, 52 eligible
`checkout_lead` leads.

**No campaign has ever been created for either event** — `broadcast` has zero rows for both
event ids. So today's actual delivered follow-up count is 0, not "a few"; "a few" is what the
organizer would see *if* they composed one, because of the audience gap above.

### This is a documented decision, not a bug

`docs/product/event-broadcast-followups.md` §4, "Expired and cancelled orders are not
targeted," states this exactly: `EVENT_UNPAID_ORDERS` is deliberately restricted to live PENDING
because "an expired order's hold is released and 'finish your payment' would point at something
that cannot be paid" (session-057's own reasoning, confirmed by reading `repo.ts`'s inline
comment verbatim). It also states the intended next step — reach expired-order buyers with a
**MARKETING** message instead of a UTILITY reminder — was deliberately deferred because **no
consent field exists on `orders`** (there is nowhere on the checkout form for a buyer to tick a
marketing opt-in), and widening the predicate without solving that first would misrepresent
`order_payment_reminder`'s UTILITY category to Meta — a real WhatsApp-quality risk, not a
cosmetic one.

Separately, §1 of the same doc records that the *automatic* nudge (firing 30–60 min after
abandonment, which is what would actually move the needle — "abandoned-cart recovery is
dominated by latency") was also deliberately left out of the first release; today every
follow-up, including the 53-lead "Abandoned checkouts" audience, requires the organizer to
manually open the composer and press send. Nobody has yet.

## Root cause (proven, not inferred)

1. **Coverage gap, by design, not implemented:** EXPIRED orders (order-derived leads) have no
   broadcast audience path — `EVENT_LEADS` only reads `checkout_lead`, `EVENT_UNPAID_ORDERS`
   only reads live `PENDING`. For this event that hides 220 of the ~273 broadcastable-looking
   leads (220 expired orders + 53 eligible checkout leads) from any bulk send.
2. **No trigger, by design:** even the reachable 53 need a human to compose and press send —
   there is no scheduled/automatic fan-out yet, and none has run for this event.
3. Both are pre-existing, explicitly documented limitations (`event-broadcast-followups.md`
   §§1, 4) from the feature's own launch — not a regression introduced by any later deploy, and
   not something this session changed.

## Recommendation (not yet implemented — analysis only, per user's request)

- **Close the EXPIRED-orders gap deliberately, gated on marketing consent** — the doc's own
  §4 already names the fix: add a marketing-consent checkbox somewhere in the order/checkout
  flow (or reuse the `checkout_lead.consent_marketing` a buyer may have already set earlier in
  the same session, if one exists for that phone), then either (a) widen `EVENT_LEADS` to also
  source consented EXPIRED/CANCELLED orders the way the organizer-facing Leads *list* already
  does (`unconvertedOrderWhere`, in `events-leads/repo.ts`), or (b) add a third audience kind
  (`EVENT_EXPIRED_ORDERS`) so it stays a MARKETING-only, explicitly-gated send and never risks
  `order_payment_reminder`'s UTILITY classification. Given 220 of this one event's ~273
  reachable-looking leads sit in this bucket, this is the highest-value fix available.
- **Prioritize the automatic nudge (§1)** once the above exists — the doc itself says latency
  dominates conversion here, and the schema (`checkout-lead.ts` sweep, `broadcast`/
  `audience_kind`/`audience_config`) is already shaped for it.
- **Short term, no code change needed:** the organizer can compose an "Abandoned checkouts"
  campaign today and reach 45–53 real people, and can still manually chase the 220 expired-order
  leads one by one from the **Leads** page — that path already works and has simply never been
  used for this event.
- **Separately worth flagging to the user:** the duplicate "Festival Mbois 11 - Concert" /
  "…by BRImo" listings split the same audience across two events (53+52 checkout leads, 220+296
  expired orders) — any leads/broadcast fix should account for both, or the organizer should
  confirm whether the duplicate listing itself needs consolidating (a pre-existing, previously
  flagged condition — see README "Open follow-ups").
