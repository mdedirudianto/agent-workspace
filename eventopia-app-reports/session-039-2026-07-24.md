**Bug found — v3 fallback misclassifies its own "not activated" error as retryable.** BCA came
back `503 PAYMENT_GATEWAY_UNAVAILABLE` ("silakan coba lagi") instead of the correct
`422 PAYMENT_METHOD_NOT_ACTIVATED` ("belum aktif, pilih metode lain"). Traced it by hand: a raw
`curl .../v3/payment_requests` with `channel_code: BCA_VIRTUAL_ACCOUNT` on the platform key
returns `{"error_code":"INVALID_MERCHANT_SETTINGS", ...}` — a code the app's
`CHANNEL_NOT_ACTIVATED_CODES` set doesn't recognize (it only lists Fixed VA's codes:
`BANK_NOT_ACTIVATED_ERROR`/`CHANNEL_NOT_ACTIVATED`/`PAYMENT_METHOD_NOT_ACTIVATED`). So when a bank
is dead on **both** Fixed and v3 (only BCA today), the v3 attempt's error escapes classification
and falls through as a generic `PaymentProviderError` → 503, telling the buyer to retry something
that can never succeed. Narrow blast radius — every bank actually rescued this session
(BRI/BNI/MANDIRI/PERMATA platform-side, BRI on MCF) takes the correct 2xx path; only a bank dead
on both surfaces trips it. **Filed in the app repo**, `docs/engineering/known-issues.md`, commit
`2dfcb741` (not pushed — see Open follow-ups).

**E-wallet failures were my test's fault, not the app's.** My first pass omitted fields the real
web checkout always sends: `returnUrl` (required for GOPAY/DANA/SHOPEEPAY, read straight from the
request body per `apps/api/src/modules/payments/contract.ts`) and a buyer phone on the *order*
(required for OVO, read from `order.buyerPhone`, set via `CreateOrder.buyer.phone` — I hadn't
populated it). Retried with both fields present: all 4 correctly returned
`422 PAYMENT_METHOD_NOT_ACTIVATED` — meaning e-wallets are genuinely **not activated at all** on
the platform Xendit account. This is a Xendit-dashboard gap (parallel to the BCA VA gap), not a
code bug — not filed in `known-issues.md` (that file is for code bugs); noting it here as an
operational fact for the platform account.

## Findings summary

1. **Confirmed live and working:** session-038's deploy does what it was built for — MCF's BRImo
   mints via v3 where it used to 422, platform PLATFORM-mode QRIS/VA(4 banks)/BRImo all mint real
   Xendit artifacts, per-bank VA selection works for every activated bank.
2. **Real bug, filed:** v3's `INVALID_MERCHANT_SETTINGS` not-activated code isn't recognized,
   causing a wrong 503-retryable instead of 422-terminal for banks dead on both VA surfaces.
   `docs/engineering/known-issues.md` commit `2dfcb741` in the app repo.
3. **Not a bug, operational fact:** e-wallets (GOPAY/OVO/DANA/SHOPEEPAY) are not activated on the
   platform Xendit account at all — correctly rejected, just unavailable until someone flips them
   on in the Xendit dashboard.
