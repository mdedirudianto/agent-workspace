### Real test send — found a real bug

User asked for an actual send to a real number to verify the buttons render correctly (the
highest-risk new surface per the deploy note). Wrote a small ephemeral script calling
`createWhatsAppClient(...).sendTemplate(...)` directly with real prod config — the same
pattern prior sessions have used to exercise a real code path without minting production data
— sent both templates to `+6285338155153` using a real published event's short code
(`ZFJB2K`) for the button link. Both delivered with real Meta message ids. Removed the
ephemeral script immediately after.

**The returned `estimatedCost` was Rp 6,150 for the MARKETING send — the user flagged this as
obviously too high.** Traced to `packages/whatsapp/src/cost.ts`:

- **Units bug.** The file's own comment claimed values were in *sen* (1/100 rupiah) —
  `MARKETING: 61_50` meant "Rp 61.50". But nothing downstream (`materialize.ts`,
  `events-broadcast/module.ts`, or any other money surface in this repo — see session-054's
  identical-shaped GA revenue bug) ever divides by 100; the whole codebase's convention is
  `minor == rupiah`. So the constant rendered as **Rp 6,150**, ~10× too high.
- **Stale rates on top of that.** Even at the correct scale, Rp 61.50 would still be wrong —
  Meta's real current per-message rate for Indonesia is **Rp 586.33** (MARKETING) and
  **Rp 356.65** (UTILITY/AUTHENTICATION, priced identically in this market).

**Already diagnosed and fixed in an unmerged branch.** `feat/wa-message-billing`
(`.worktrees/wa-billing`, part of a much larger, still-in-progress billing/credit-metering
feature — 12 migrations, "1 of 4 plans built") had already found and fixed exactly this bug,
with a corrected rate card in whole rupiah. Confirmed the fix was safe to cherry-pick in
isolation without pulling in the rest of that branch: no caller assumes the old scale,
`path.ts`'s `selectCheapestPath` never reads the rate values (only picks a category), and the
existing test only asserts internal consistency (`estimateCost(...) === RATE_CARD_IDR.ID.MARKETING`),
not a literal old number.

Applied just the `cost.ts` correction on `main` — whole-rupiah units, Meta's current ID rates
(586 / 357 / 357), rewritten doc comment explaining both bugs and citing the money-convention
precedent elsewhere in the repo. Found and fixed **3 test files** that had hardcoded the old
`6150` literal locally instead of importing `RATE_CARD_IDR` (`crm-broadcast.test.ts`,
`crm-broadcast-spend.test.ts`, `crm-materialize.test.ts`) — switched all three to import the
real constant so this can't silently drift again. Ran the full `apps/api` + `packages/whatsapp`
test suites (2694 pass, 4 pre-existing unrelated failures in `ticket-code-drift.test.ts`
confirmed via `git stash` to already fail on clean `efbadb1a` — a CWD-resolution quirk in that
one file, nothing to do with this change).

Committed (`122b0e2a`), pushed, pulled on `app`, restarted `api`+`workers` (the only consumers
— `console`/`workers` themselves never import the estimator, confirmed via grep; workers
restarted anyway since it shares the same monorepo package). Verified live on prod via a direct
`bun -e` snippet: `RATE_CARD_IDR.ID` now reads `{ MARKETING: 586, AUTHENTICATION: 357, UTILITY:
357 }`.

## Findings summary

1. **Broadcast cost estimates were ~10× too high platform-wide** since the event-broadcast
   feature shipped (session-057) — every organizer previewing a campaign, and every workers
   log line recording a real send, showed Rp 6,150/message instead of the real ~Rp 586. Fixed
   and deployed.
2. **The correct fix already existed, unmerged**, inside a much larger in-progress billing
   feature — worth remembering next time a `feat/wa-message-billing`-adjacent bug surfaces,
   since that branch may already have diagnosed it.
3. **Three tests hardcoded a value that should have been imported** — the kind of drift that
   let this bug hide behind a green test suite (the tests were internally consistent with the
   wrong number, not checked against reality). Fixed to import the source of truth.
