## Gotchas hit

- `/root` is `700` on `db` — `sudo -u postgres pg_dump -f /root/eventopia-backups/...` fails with
  a misleading "Permission denied" even though the target directory itself is `postgres`-owned and
  writable; the actual blocker is that `postgres` can't traverse `/root` at all. Worked around by
  dumping to `/tmp` (world-traversable) and moving the finished file in afterward.
- Manually enqueuing a BullMQ job needed the script to run from *inside* `apps/workers` (not the
  repo root or a scripts dir) so `bullmq` resolves from the workspace's own `node_modules`.
- Console build did **not** OOM this time (unlike session-067) — building it alone, not chained
  with api/workers/checkin, and with a capped heap, kept swap usage from repeating that incident.
