## Why

`PIN_PEPPER` was echoed into a session transcript in session-069 and left unrotated (session-070 follow-up 3). The pepper is what protects PIN hashes if the database leaks: a 6-digit PIN carries about 20 bits, so without the pepper a dumped `account.pin_hash` falls to offline cracking (header of `apps/api/src/platform/auth/pin.ts`).

The user's concern (2026-10-19) was that a rotation would lock users out, and that if a reset were truly needed, the PINs should be cleared to "not set" instead. The code check showed no reset is needed:
- `loadPinPepper()` reads `PIN_PEPPER_PREVIOUS` (`pin.ts`).
- `verifyPin()` tries the active pepper first, then the previous one, and reports `needsRehash`.
- The sign-in path re-writes the hash under the active pepper when `needsRehash` is set (`modules/auth/module.ts`, around L2354).

Only the api loads the pepper (`apps/api/src/container.ts`). Workers don't.
