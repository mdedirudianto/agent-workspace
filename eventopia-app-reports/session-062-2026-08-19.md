### Fixed: `bun` unreachable from any non-interactive SSH session on `app`

`apps/api`'s build script (`bun run scripts/gen-openapi.ts`) failed first try — `sh: 1: bun: not
found`. `~/.bun/bin` is only added to `PATH` inside `~/.bashrc`, and Debian's default `.bashrc`
has the standard `[[ $- != *i* ]] && return` guard at the top — so a plain `ssh host "cmd"` (no
tty, non-interactive) never sources it, and even `bash -lc '...'` doesn't help, because `.profile`
sources `.bashrc` but the guard still fires. `node`/`pnpm` never hit this because they're installed
system-wide at `/usr/bin`, always on the default PATH; `bun` was the outlier, user-installed under
`~/.bun`. Fixed at the root rather than patching around it: symlinked `bun`/`bunx` from
`/usr/local/bin` (root-owned, on every shell's PATH by default) to `/home/devops/.bun/bin/bun`,
matching how node/pnpm already resolve. Verified: plain `ssh devops@app "bun --version"` now works
with no PATH juggling — this was silently one bad build away from breaking any future deploy that
touches `apps/api`'s OpenAPI generation step.
