## Findings summary

1. **The riskiest migration in the batch (0118's partial-index rewrite) proved itself correctly on
   real traffic** — both crew-invite paths (email, phone) returned 201 immediately after the
   api+workers restart, with zero window where the old code could have hit the documented 500.
2. **A `git log` check on the verifier file turned a scary-looking `CHAIN BREAK` alert into a 30-second
   non-event** — confirming the hash-chain verifier code was unchanged in this deploy meant the break
   couldn't be new, and the README's session-017 follow-up confirmed it by date.
3. **`infra/DEPLOY.md` documents an aspirational Docker-Compose target, not what prod runs** — it says
   so explicitly ("this runbook describes the COMPOSE target, which is not what production currently
   runs"). Confirmed the real path is still `git pull` + `pnpm build` + `pm2 restart`, migrations via
   `packages/db/run-migrate.mjs` from `packages/db` (not the drizzle-kit CLI, a known-flaky path).
4. **No browser extension was available this session**, so the two purely-presentational fixes (custom
   HTML canvas, PIN centering) and the live gtag network request were verified via build artifacts
   (compiled bundle greps, the build-time browser-baseline guard) rather than a real rendered page.
   Lower confidence than a visual check, but consistent with what the code demonstrably shipped.
