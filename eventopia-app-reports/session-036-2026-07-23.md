## Goal

End-to-end smoke test: event creation → checkout → payment, for **QRIS** and **VA (BRI)**,
confirming each hits the real Xendit API with zero errors, using the **platform** Xendit gateway
(not an organizer's own DIRECT key). Revised mid-planning after confirming the generic `VA`
method has no bank selection (hardcoded BCA) — expanded to also cover the generic VA channel
as-is, a raw BNI/BRI diagnostic bypassing the app, and filing the hardcode as a known issue.
Explicitly scoped to stop at "real payment intent created" — no real money moved (prod's Xendit
key is live/production).

## Gotchas hit

- `pnpm --filter`-style env sourcing isn't the pattern here (no pnpm needed), but `source .env`
  over SSH partially fails on this `.env` file (an unescaped `<...>` in `EMAIL_FROM` breaks bash
  parsing mid-file) — silently drops later variables. Worked around by extracting individual vars
  via `grep | cut` instead of sourcing the whole file, same fix pattern as session-033's
  `db:migrate` gotcha.
- `scripts/xendit-channels.ts` needs `XENDIT_WEBHOOK_TOKEN` set (not just `XENDIT_API_KEY`) —
  `loadXenditConfig()`'s `configured` check requires both.
- `bun` isn't on `PATH` in a non-interactive SSH shell — needs the explicit `~/.bun/bin/bun` path
  (same as session-009's documented gotcha).
