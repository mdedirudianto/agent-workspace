## New gotcha (worth carrying forward)

**`pm2 restart <name> --update-env` does NOT re-read `ecosystem.config.cjs`.** This repo's ecosystem file computes `env` by parsing `.env` itself at *config-load* time (`parseEnv()` in the file, not PM2's own dotenv support), and merges that into each app's static `env:` object. `pm2 restart <name>` (by process name/id, without pointing at the config file) reuses PM2's already-cached process definition — `--update-env` in that form only refreshes from the *current shell's* exported env, not from the on-disk `.env`. The fix, and the one to use whenever `.env` changed and the ecosystem file wasn't itself edited: `pm2 restart ecosystem.config.cjs --only <name1>,<name2> --update-env` (or `pm2 reload ...`, same effect), which re-executes the JS config file end to end. Sessions 008/013 hit an adjacent version of this same class of bug; this session is the first to nail down the exact mechanism and the exact one-line fix. **Always verify with `pm2 env <id>` after an env-only restart, not just `pm2 list`'s "online" status** — the process comes up fine either way; only the env content differs.
