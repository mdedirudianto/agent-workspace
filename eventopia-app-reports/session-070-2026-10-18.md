## DB password rotation (user authorised "rotate yourself afterward")

Why: during pre-flight a quoting mistake made `psql` print the full prod `DATABASE_URL` (password included) into the
session transcript. Procedure: new 48-hex password generated **on `app`** (never in the session); SCRAM-SHA-256
verifier computed there with python; `ALTER ROLE eventopia PASSWORD '<verifier>'` on `db` over stdin (precomputed
verifier, and `log_statement=none`); new password proved to authenticate **and old one rejected** *before* touching
`.env`; `.env` `DATABASE_URL` password replaced in place (regex asserted exactly one match, file mode preserved);
`startOrRestart` api + workers; temp file `shred`ded. Consumers checked first: only `app` (10.0.0.5, `postgres.js`,
20 conns) used the role; admin/console/web-public have no direct DB use. Verified after: `readyz` db true, directory
API + tenant hub 200 (real DB traffic), 11 sessions from `app`. The only `authentication failed` lines in the PG log
are the two from the deliberate old-password probe.

## Findings / gotchas

- **Operator console host is `admin.eventopia.co.id`**, not `operator.eventopia.my` (retired in session-013; the old
  host 404s by design). The first `/login` hit on `admin…` right after the restart returned curl `000` (11 s cold
  start), then 200 ×3.
- **Credential echo, again.** `P="psql -F' | ' $U"` split the command line and psql echoed the URL. Saved as memory
  `feedback_psql_on_app_never_echo_db_url` (quoted-var function + a redaction `sed` on every ssh output).
- **`tr -d "\x27"` is not an escape in GNU tr** — it deleted `x`, `2`, `7` from a key (caused a bogus Xendit 401 and a
  bogus "13-digit number is 8 long"). Strip quotes with `sed`, never `tr`.
- The consent backfill needed `set -a; . ../../.env` before `bun run` from `apps/api`.
- A leftover watcher from session-069 (`until ! pgrep … next build … tail build-web-public-4983acef.log`, 5 days old)
  was running on `app`; harmless, exits when builds stop.
- Server (`app`) log timestamps are CEST (UTC+2), WIB = +5 h from them.
- The OpenTelemetry "duplicate registration" lines at api/workers startup are **pre-existing** (session-069).
- A home-wide `grep -r` on `app` runs for minutes (40 PM2 apps' repos); search only the specific paths.
