## What drove this

54 commits had landed on `origin/main` since session-014's `b10d49f`, headlined by two features:

- **Add-on quantity + PER_UNIT/PER_UNIT_NIGHT pricing** (bulk of the commits): add-ons previously
  fixed at quantity 1 now get a quantity stepper; two new price-unit types (`PER_UNIT`,
  `PER_UNIT_NIGHT`) join the existing per-stay/per-night units, priced via a new shared
  `unitMultiplier` helper (`packages/utils`). Threaded through the Zod boundary, all 3 booking-create
  routes, `resolveAddOns` pricing, and every consumer: `packages/hotel-types`, `packages/hotel-ui`,
  `apps/public`, `apps/web/technopark`, `apps/web/bwalk`, `apps/management` (add-on editor + booking
  add-on line preview). Includes a related UX fix: the Extras/add-ons wizard step is now skipped
  entirely (stepper + routing) when a hotel has zero add-ons configured, instead of showing an empty
  step.
- **New: Avilia affiliate-webhook integration** (backend only, `AviliaWebhookService`): emits 6
  best-effort booking lifecycle events (`booking.created/paid/fulfilled/cancelled/no_show/refunded`)
  to an external affiliate-OS, gated on the booking carrying an `affiliateLinkId`. **Fail-closed**:
  reads `process.env.AVILIA_ENABLED` directly with an inline guard (confirmed by reading the source,
  not just env schema) — a no-op unless `AVILIA_ENABLED=true` *and* per-hotel
  `AVILIA_EVENTS_URL`/`AVILIA_SERVICE_ID`/`AVILIA_SERVICE_SECRET` are set. Delivery failures are
  caught and logged, never thrown. Enabling is per-hotel and requires that hotel to be provisioned
  in Avilia first — **none of the 3 hotels are provisioned yet**, so left disabled this session (user
  decision).

**Migration:** one additive-only enum migration (`ALTER TYPE "AddOnPriceUnit" ADD VALUE 'PER_UNIT'`,
`'PER_UNIT_NIGHT'`) — no backfill, no downtime.

**Dependencies:** `pnpm-lock.yaml` +255 lines — real new deps in `packages/hotel-ui`, `apps/public`,
`packages/utils` (unlike session-014's no-op install).

Confirmed before starting: no new required env vars (Avilia vars are optional/fail-closed, verified
in source); `packages/hotel-ui` and `packages/hotel-types` are consumed as raw TS source (no build
step) — only `packages/utils` and `packages/types` needed `build:packages` before the backend would
compile.

future sessions: any commit touching `packages/utils` needs `build:packages` before `apps/backend`
builds, since session-014 never needed it (no utils changes that session).
