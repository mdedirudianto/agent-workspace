## What drove this

The Avilia webhook code has shipped dormant since session-015 (booking events) and session-017
(affiliate sync). Wiring it for real surfaced two Hoteru-side bugs that had to be fixed first:

- **Rejected webhooks were invisible.** `emit()` and `syncAffiliate()` never inspected the response.
  Avilia signals a bad secret, an unprovisioned service or clock skew with a **non-2xx response**,
  not a thrown error — so the existing `try/catch` never fired and a misconfigured hotel was
  indistinguishable from "no affiliate bookings yet". Both call sites now log status + body via
  `logIfRejected`, which is itself wrapped and can never throw into the booking path (the
  fail-closed, best-effort contract is preserved). Verified: with a wrong secret the emitter
  previously produced **0** log lines, now **1** (HTTP 401).
- **A genuine 0% affiliate was billed at 10%.** `defaultRateBps: rateBps > 0 ? rateBps : 1000`
  treated a real 0% rate as "missing". Technopark has exactly such an affiliate. Only a non-finite
  or negative rate falls back now.
