## What drove this

Client-reported: referral/affiliate links for the Technopark Malang tenant landed on an unrelated
personal domain (`dinoudon.my.id`) instead of the hotel's real site. Root cause:
`apps/web/technopark/src/app/r/[slug]/route.ts` validates the incoming `x-forwarded-host` against
a `TRUSTED_ORIGINS` allowlist before doing a same-origin 307 redirect; `technoparkmalang.hoteru.co.id`
wasn't in that allowlist in the deployed build, so every hit fell through to the hardcoded fallback
literal, `'https://technopark.dinoudon.my.id'` — baked in at Next.js build time, not fixable via
env var. The fix (swap the literal for the real domain) was already on `origin/main`, bundled with
3 other unrelated commits (no schema/migration changes in any of the 4):

| `a8646a1` | `feat(affiliates)`: Approve/Mark-Paid commission buttons + default commission-rate fallback |

### Recurring bug: tenant clone's git fetch refspec doesn't track `main`

Same root issue session-004 hit and only partially worked around: `~/hoteru-technopark`'s
`remote.origin.fetch` was scoped to a single ref, `+refs/heads/feat/integration-area-a-b:...` —
the original integration branch this tenant was first built from. GitHub deleted that branch
after it merged, so **any plain `git fetch`/`git pull` on this clone has been failing outright**
ever since (`fatal: couldn't find remote ref refs/heads/feat/integration-area-a-b`), and local
`main` had no upstream tracking configured at all (`branch.main.remote`/`.merge` both empty).
Session-004's fix (`git switch -c main origin/main`) got that session unblocked but didn't
address the underlying refspec — it was bound to break again on the next deploy, which it did.

**Fixed properly this time:**
```
git fetch origin main:refs/remotes/origin/main   # bypass the broken default refspec
git merge --ff-only origin/main                  # 124d070 → ca72aa1
git remote set-branches --add origin main        # add main to the tracked-branch list
git branch --set-upstream-to=origin/main main     # give local main real upstream tracking
```
`git fetch`/`git pull` on this clone should now work normally going forward without a workaround.
