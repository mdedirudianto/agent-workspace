## What drove this

4 commits had landed on `origin/main` since session-010's `a57b217`:

- **`feat(purge)` (`5188dbb`):** a per-tenant `SUPERADMIN` role (ranked above `ADMIN`) — the only
  role that may permanently hard-delete already-soft-deleted data. New `requireSuperAdmin` auth
  decorator; new `/api/purge/{bookings,rooms,room-types,gallery}` routes (`GET` + `DELETE`),
  tenant-scoped and gated `[authenticateStaff, requireHotelContext, requireSuperAdmin]`. Only rows
  already soft-deleted are purgeable (cancelled/no-show bookings; inactive rooms/room-types/gallery);
  a room is refused while any booking references it, a room type while any room/booking references
  it. New management SPA `/trash` page (`SUPERADMIN`-gated).
- **`fix(bwalk)` / `fix(technopark)` (`bca750a`, `eb32a39`):** `useScrollAnimation`'s intersection
  threshold was `0.1` (10% of the element must be visible to trigger the fade-in reveal). On a tall
  single-column mobile grid, the max reachable intersection ratio is `viewport / element` — for
  grids much taller than the viewport, `0.1` is unreachable and the reveal never fires, leaving the
  whole room list stuck at `opacity-0` (invisible) on phones. Bwalk hit this live (9 room types,
  confirmed bug); Technopark was latent (only 3 room types, not yet tall enough to trigger). Fixed
  to `threshold=0` on both.

No `package.json`/lockfile changes, no new dependencies.

## SUPERADMIN accounts created (post-deploy follow-up, closed same session)

account is a required manual step post-deploy — the seed doesn't run on redeploy, and running
`db:seed` in prod would `deleteMany` first, wiping real data. The initial attempt at the raw
`INSERT INTO users (...)` was blocked by the harness's auto-mode safety classifier (writing a
password hash to a production table); re-attempted after the user explicitly took the session out
of auto mode and asked directly for it, and succeeded via `psql` heredoc over SSH (no file staged
with the hash — avoided writing it to disk anywhere).
