# Session 1 — Actions minutes exhausted on `biji-dev`; all CI + Dependabot disabled

**Date:** 2026-09-20
**Scope:** GitHub org `biji-dev` (Free plan) — 24 private repos
**Trigger:** Every CI run since the grobiz merge died in ~3–6 s with *"recent account payments have failed or your spending limit needs to be increased."*

---

## Root Cause

Nothing had failed to charge. `biji-dev` is on **GitHub Free**, had used **2,000 / 2,000 included Actions minutes** (resets ~2026-10-01), has **no payment method on file** ("You have not made any payments"), and its Actions budget is **$0 with Stop usage = Yes**. With the allowance gone and no permitted overage, every job is refused at start. The personal account (`mdedirudianto`) was fine ($0 usage, Visa valid to 8/2027) and was not involved.

## What Burned the Minutes (Sept 1–29, $14.73 gross)

| Repo | Gross | Main consumers (wall-clock, approximate) |
|---|---|---|
| grobiz | $12.68 (86 %) | CI on push 80 runs ≈ 660 min (71 failed); Deploy on push 80 runs ≈ 540 min (69 failed); Dependabot ≈ 5 large runs ≈ 264 min; Maestro Android nightly 20 runs ≈ 164 min (**20/20 failed**); CI on PR 17 runs ≈ 89 min (all failed) |
| ytgrab | $0.80 | CI/Deploy/nightly, mostly failing |
| max, asiaweek, hoteru, other | $1.24 | minor |

Aggravators: no `cancel-in-progress` concurrency on grobiz `ci.yml`; three grobiz nightly cron workflows; Dependabot weekly npm + github-actions with `open-pull-requests-limit: 10`.

## Decision

User decided CI is not needed at the moment: **disable all workflows and Dependabot** rather than pay for minutes. Disable, not delete — YAML stays in the repos, fully reversible. Deploys in this fleet are pull-based from a server checkout, so the Actions `Deploy` workflows were redundant. No branch protection / required checks exist on these private Free-plan repos (API returns 403), so disabling cannot block merges. Public repo `ecc-js` (fork-ci, fork-sync) left untouched — public repos run free.

First attempt at step 2 made no API calls: the loop used `path` as a variable name, which in zsh is tied to `$PATH`, so `gh` stopped resolving. Renamed the variable and reran; verified from GitHub, not from exit codes.

## Re-enable / Rollback

```bash
# Re-enable everything in one repo
gh workflow list -R biji-dev/<repo> --all --json id,state --jq '.[]|select(.state=="disabled_manually")|.id' \
  | while read -r id; do gh workflow enable "$id" -R biji-dev/<repo>; done

# Restore grobiz Dependabot config
git show ed0a11a^:.github/dependabot.yml > .github/dependabot.yml
```

Before re-enabling, fix the waste first: add `concurrency: cancel-in-progress` to grobiz CI, fix or drop the Maestro nightly (it failed 20/20), drop `Deploy` workflows that duplicate the pull-based deploy, and reduce Dependabot cadence. Or add a payment method at `https://github.com/organizations/biji-dev/settings/billing/payment_information` and raise the Actions budget above $0.
