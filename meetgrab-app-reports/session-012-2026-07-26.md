## Findings beyond the deploy

### 1. Web GlitchTip DSN had silently regressed — fixed

The live `e396aaa` bundle contained **no reference to `errors.biji.uk` at all**. GA4 was present; web error tracking was dead, despite the README recording it as a completed follow-up ([x], session-001). Validated the documented DSN still works (POST to project 16 → **HTTP 200, event ingested**) and baked `PUBLIC_GLITCHTIP_DSN_WEB` back into this build. Web error tracking is live again.

### 2. Admin rebuilt with the wrong API base — self-inflicted, caught and fixed

Rebuilding `apps/admin` as part of the turbo build baked **`http://localhost:8930`** into the
deployed bundle. Root cause: admin reads `VITE_API_BASE_URL`, which **defaults to localhost** in
`apps/admin/.env.example`, and I hadn't exported it. Caught by diffing the new artifact against the
pre-deploy backup:

```
new build       → http://localhost:8930      ← broken
backup (old)    → https://api.meetgrab.us    ← correct
```

Rebuilt with `VITE_API_BASE_URL=https://api.meetgrab.us`, redeployed, verified. Same root cause as
the GlitchTip regression above: **neither `apps/web` nor `apps/admin` persists build env on the
server** — only a `.env.example` — so a forgotten export produces a working build with wrong config
and no error. Recommended a checked-in `.env.production` or a build-time assertion.

Also corrects a long-standing README error: the ops README claimed `VITE_ADMIN_TOKEN` is baked in.
**No such var exists** — admin reads only `VITE_API_BASE_URL` and `VITE_GLITCHTIP_DSN_ADMIN`, and
the metrics token is pasted at runtime into `sessionStorage`. (The old build had no admin GlitchTip
DSN either, so leaving it unset matches prior state.)

### 3. Summary canary message broke on the new response shape — fixed

The poll payload changed from `{state, summary}` to `{state, result:{summary, decisions, actionItems, followUps, …}}`. The canary read the top-level key, so its Uptime-Kuma message went empty. It still gated correctly on `state==done` (no false DOWN), so this was cosmetic — patched `~/meetgrab-summary-canary.sh` to read `result.summary` (backup: `.bak-20260726`). Now reports a real excerpt.

`OPENPANEL_API_URL` already defaults to the self-hosted `https://analytics.biji.uk/api` in code

### 5. Sonnet 5 switch attempted → **rolled back** (SDK incompatibility)

User asked to move summarization to Sonnet 5 (after I flagged Opus 5 as a poor fit — see below). Pre-verified on the prod OAuth path: **accessible, HTTP 200, `thinking_tokens: 0`, no truncation risk**, and at $3/$15 it matches the existing `ANTHROPIC_SONNET_COST_PER_1M_*` values so the spend ledger stays correct with no env change. Applied via env only and restarted.

**Every summary failed instantly** (`LLM_UNAVAILABLE`, `latency=0`, `cost=0`, fallback never engaged). Reproduced directly against the installed SDK:

```
claude-sonnet-5 → 400: "`temperature` is deprecated for this model."
```

**Root cause:** the Vercel AI SDK v4 (`ai@4.3`, `@ai-sdk/anthropic@1.2.10`) sends a default `temperature` on every call, and Sonnet 5 rejects sampling parameters outright. **No env change can fix this — it needs a code change or an SDK upgrade.** Rolled back to `claude-sonnet-4-6` and verified restored (`done`, 10s, 671 chars).

**Impact: zero users.** All 7 summary requests today came from a single ipHash (`a3c9655b1935fcdb` = the app server itself) and all 6 install IDs were session test UUIDs. The ~2-minute window hit only my own test traffic. This is precisely why the model switch was sequenced *after* the deploy rather than folded into it.

### 6. Why Opus 5 was rejected before it was tried

Originally asked for Opus 5. Empirical probe on the prod OAuth path found it emits `thinking` by default — **1004 of 2000 output tokens (50%) went to thinking, `stop_reason: max_tokens`**. Since the summary path parses a structured `SummaryDoc`, truncation means a *failed* summary, not a shorter one. Plus: `cost.ts:35` charges any non-Haiku Anthropic model at the Sonnet rate ($3/$15) while Opus 5 is $5/$25 — the spend cap would have undercounted ~40% (the code comment anticipates exactly this: *"Adopting Opus would warrant its own (higher) rate vars"*). Flagged; user redirected to Sonnet 5.
