### New finding — pnpm store had an orphaned version dir

`~/Library/pnpm/store` held three lockfile-format version directories: v3 (1.3GB), v10 (1.0GB), v11 (1.7GB) — 4.1GB total, despite `pnpm --version` reporting 10.30.1 as the active CLI. Manual staleness-by-mtime investigation was inconclusive and slow (v11's file count made `find` time out), so `pnpm store prune` was used instead of guessing:

- Removed 65,882 cached metadata files and 1,289 orphaned packages
- **v10 emptied to 8KB** — no current project referenced it
- **v3 (1.3GB) and v11 (1.7GB) were left untouched** — `pnpm store prune` determined they're still referenced by lockfiles in existing projects, disproving the initial hypothesis that v3 was a stale leftover

**Lesson:** for pnpm store dirs, trust `pnpm store prune`'s own reference-tracking over manual mtime inspection — multiple lockfile-format versions can be legitimately live at once across different projects.
