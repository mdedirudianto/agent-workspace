# Session 37 — Build-Cache Sweep Across Active Projects (ytgrab/eventopia/grobiz) + Regrowable Tool Caches

**Date:** 2026-07-22

**Disk before:** 98% used — 5.5GB free
**Disk after:** 85% used — 32GB free
**Recovered:** ~22-26GB

---

## Context

Disk hit crisis level again (5.5GB free / 98% used) despite S35/S36 having freed ~15.7GB two days earlier. User flagged three active projects (ytgrab, eventopia, grobiz) up front, which shaped the whole sweep: rather than touching git state, dependencies, or anything currently serving, this session hunted for **build caches** (`.next`) — fully regenerable output that had quietly ballooned inside active worktrees, plus the usual regrowable tool caches (gradle, npm, codex-runtimes, Docker images).

Before touching anything, checked `lsof -iTCP -sTCP:LISTEN` to confirm no Next.js dev server was actually serving from any `.next` directory being considered (only grobiz's Vite dev servers were live, ports 4710-4716) — so every `.next` removal below was against cold/unserved build output.
