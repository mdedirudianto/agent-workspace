## Anomalies

1. **SSH password auth on, root login on, no fail2ban, port 22 open to the world.** This is the only internet-exposed admin surface without an allowlist.
2. **Redis has no auth** (`protected-mode no`, no requirepass). It's bound to 10.0.0.1 and UFW-limited to monitor/app/numa, so any process on those hosts can read or flush any db.
3. **MongoDB runs without authorization**, reachable from app + backup.
4. **ClickHouse `default` user host `::/0`.** It's reachable from the root shell without a password flag; I didn't check whether it has a password. UFW limits it to monitor.
5. **ClickHouse `system` logs = 71.5 GiB** (trace_log + text_log = 54 GiB) against 243 MiB of real `openpanel` data. No TTL appears to be set on the system log tables; this is the biggest disk consumer after `wagrab`.
6. **DB admin UIs exposed via Cloudflare** on `db.biji.uk` (phpMyAdmin, pgAdmin4, mongo-express).
7. **Shared Redis db0** mixes pasarbesar queues, ytgrab rate limit (including numa 10.0.0.7) and duitkas baznas (per docs). The other dbs are single-owner.
8. **Redis db7 (seenow prod per docs) has 0 keys and 0 clients**, which suggests seenow's Redis isn't connected or is idle. Worth checking `REDIS_URL` on `app`. dbs 8–11 (hoteru) each have one client and no keys.
9. **Next free Redis db: 12** (12–15 unused). No `maxmemory` and `noeviction`, with AOF off.
10. **PG DBs with 0 connections at survey time:** `ytgrab_prod` (669 MB, owner `postgres`), `verify_wagrab_484379` (130 MB, owner `postgres`, looks like a leftover restore-verify DB that can be dropped), `meetgrab` (docs say meetgrab has no DB, so this may be dead), `pasarbesar`, `pasarbesar-lpekinhub`, `miawflow_baznas`, `miawflow_lpekin`, `pahala`. pahala, duitkas and pasarbesar may just connect on demand.
11. **`ytgrab_prod` owned by `postgres`**, with no app role, so the app probably connects as superuser or the DB is dead. ytgrab-api runs as root on db itself.
12. **backup_reader**: exists, `pg_read_all_data` + BYPASSRLS, and can CONNECT to every DB (via PUBLIC). No gaps.
13. **PUBLIC CONNECT on all DBs**, so every login role can connect to every database.
14. **pg_hba**: `local all postgres trust`. There are three redundant `10.0.0.x/22` lines and an over-broad public `/21` md5 line, which is dormant only because Postgres doesn't listen on the public IP. Auth is `md5` rather than `scram-sha-256` for the private range.
15. **PG timezone Asia/Singapore ≠ OS Asia/Jakarta**.
16. Superusers: only `postgres`, as expected. `seenow` has CREATEDB + CREATEROLE + BYPASSRLS, which is broader than the other owner roles (documented as intentional for migrations).
17. **MariaDB**: 52 ERPNext site DBs live here, not on `erp`. Site users are `@'%'`, and `root` is allowed from 10.0.0.2 (proxy), 10.0.0.3 and 10.0.0.4. Only erp can reach 3306 through UFW.
18. `bgutil-pot` listens on `*:4416` (all interfaces). It's blocked by UFW default deny but should be bound to localhost.
19. 257 upgradable packages; host uptime 396 days.
