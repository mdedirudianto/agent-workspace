## Catch-all behaviour

| Port | Block that answers unknown names | Result (probed locally) |
|---|---|---|
| :80 | `default` (`listen 80 default_server`, `server_name _`, root `/var/www/html`) | **200**, stock nginx/placeholder `index.html` (10.6 KB, 2025-12-07). Note that wildcard `*.gro.biz.id`, `*.eventopia.my`, `*.seenow.ac`, `*.hoteru.co.id` are caught by their own :80 blocks (301 to https) |
| :443, no SNI (IP access) | `00-default-catch-all.conf` (`443 ssl default_server`, `return 444`) | Handshake with **`biji.uk` cert**, then connection dropped |
| :443, unknown SNI/Host | **`eventopia-custom-domains.conf`** — `server_name custom.eventopia.my ~^.+$` | Regex names beat `default_server`, so **every unmatched host** is served the **`eventopia.my` cert** and proxied to eventopia web-public `10.0.0.5:38100`. The block has `include cloudflare-ips.conf` (22 `allow` lines) + `deny all`, so a direct hit returns 403 and only Cloudflare-fronted requests reach eventopia. Probe: `randomxyz.example.com` → 403, CN=eventopia.my. The `00-default-catch-all` 444 only fires for clients that send no SNI |

**Collision with seenow tenants:** `seenow.conf`'s `~^(?<tenant>[^.]+)\.seenow\.ac$` is a regex too, and nginx tests regexes in config order. `eventopia-custom-domains.conf` loads first (alphabetical), so `~^.+$` wins. ## Anomalies

1. **The eventopia regex catch-all takes every unknown :443 name, including seenow tenants.** `eventopia-custom-domains.conf` uses `server_name ~^.+$`, and that regex is checked before `default_server` and before `seenow.conf`'s tenant regex. Results:
   - `<tenant>.seenow.ac` gets the eventopia.my cert and the eventopia web app (403 locally; over Cloudflare it reaches eventopia). This breaks the seenow per-tenant learner routing.
   - Hostnames with no vhost (`admin.foucher.co`, `api.foucher.co`, `samara-batu.foucher.co`, `cockpit.biji.uk`, any stale DNS record) also land on eventopia.
   - The `00-default-catch-all` 444 block only catches clients that send no SNI.
2. **No deploy hook for the 16 dns-cloudflare and webroot certs.** All three hook dirs are empty, no renewal conf has a `*_hook`, and these lineages have `installer = None`. After certbot renews them, nginx keeps serving the old cert until an unrelated reload. Next ones due (renewal at T-30 d): **gro.biz.id** (renews ~10-22, expires 11-21, also has no propagation setting), **meetgrab.us** (~10-26), **erp.gro.biz.id** (~10-27), **v4.maxchat.id** (~11-01), **eventopia.co.id** (~11-07). Today every served serial matches its file.
3. **Certs under 60 days**, all within normal LE cadence and none under 30 days: admin.foucher.co 32 d, gro.biz.id 33, youtubegrab.com 34, meetgrab.us 37, erp.gro.biz.id 38, foucher.co 38, v4.maxchat.id 43, asiaweek.uk 49, eventopia.co.id 49, biji.uk 57, pasarbesar.id 58, avilia.id 60.
