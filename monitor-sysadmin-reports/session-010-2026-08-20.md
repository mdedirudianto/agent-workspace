# Session 10 — Netdata Streaming: Disable Duplicate Health Evaluation for `proxy`

**Date:** 2026-08-20
**Server:** `root@monitor` (`217.15.162.56` public, `10.0.0.3` internal)
**Goal:** `telegram-alerts` ledger pull showed netdata `web_log_1m_*` alarms firing near-identical counts on both `proxy` and `monitor` (997 vs 996 CRITICAL transitions/4d) for what should be a single event on `proxy`. Diagnose and stop the duplication.

---

## Root Cause

`proxy` streams its metrics to `monitor` as a netdata parent/child pair (`proxy`'s `stream.conf`: `destination = 10.0.0.3:19999`). `monitor` accepts the stream (`allow from = 10.0.0.*`) with `health enabled by default = auto` — which enables `monitor` to independently re-evaluate health alarms (including `proxy`'s `web_log` ratio alarms) against the streamed child data, on top of `proxy` alarming on itself. `monitor` doesn't run nginx (`systemctl status nginx` → unit not found, no `/var/log/nginx/`) — it has no `web_log` traffic of its own — so every "monitor" host entry for this alarm in the ledger was actually a duplicate notification for the same underlying `proxy` event. See [proxy-sysadmin-reports/session-005](../proxy-sysadmin-reports/session-005-2026-08-20.md) for the primary fix (widening the alarm's window/guard on `proxy` itself).

## Actions Taken

| # | Action | Detail | Result |
|---|--------|--------|--------|
| 1 | **Confirmed monitor runs no nginx** | `systemctl status nginx` → unit not found; `/var/log/nginx/` → does not exist | No local web_log source on monitor |
| 2 | **Confirmed streaming relationship** | `proxy`'s `/etc/netdata/stream.conf`: `enabled = yes`, `destination = 10.0.0.3:19999`; `monitor`'s `/etc/netdata/stream.conf`: `[e0bd45e6-d615-405b-956e-43a6e41ac474]` stanza accepts from `10.0.0.*` with `health enabled by default = auto` | Confirmed parent/child, health eval enabled on parent |
| 3 | **Backed up config** | `cp /etc/netdata/stream.conf /etc/netdata/stream.conf.bak-20260820` | Done |
| 4 | **Disabled health eval for streamed children** | `/etc/netdata/stream.conf`: `health enabled by default = auto` → `no` (in the API-key stanza) | Applied |
| 5 | **Restarted netdata** | `systemctl restart netdata` | `active` |

---

## Config Change

`/etc/netdata/stream.conf`:

```diff
 [e0bd45e6-d615-405b-956e-43a6e41ac474]
     enabled = yes
     allow from = 10.0.0.*
     default history = 3600
     default memory mode = ram
-    health enabled by default = auto
+    health enabled by default = no
```

Rationale: `monitor` still receives and stores `proxy`'s full metric stream (dashboards, history, charts all unaffected) — it just no longer independently fires its own copy of alarms that `proxy` already evaluates and notifies on for itself. Halves Telegram noise for this class of alert with no loss of detection coverage.
