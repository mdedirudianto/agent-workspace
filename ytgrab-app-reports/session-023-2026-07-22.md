# Session 23 — Rotate `RESEND_API_KEY` fleet-wide again (admin magic-link login broken, second time in 2 days)

**Date:** 2026-07-22
**Servers:** `devops@app` (10.0.0.5), `root@numa` (10.0.0.7), `root@db` (10.0.0.1)
**Trigger:** User reported admin email login failing right after session-022's redeploy, asked to check whether the Resend key was the cause.
**Result:** ✅ new key installed across all 4 `.env` copies; `ytgrab-web` (app) + `ytgrab-api` (numa, db) restarted; magic-link send verified `{"status":true}`

---

## Root cause

Same symptom as session-021 (2026-07-20) but a **different root cause**. Reproduced live: `POST /api/auth/sign-in/magic-link` returned bare `HTTP 500`, and `ytgrab-web`'s error log showed `Error: Resend send failed: API key is invalid` fired at the exact moment of the test.

This time it was **not** a propagation gap — hashed the `RESEND_API_KEY` in all 4 files (`apps/web/.env` + `apps/api/.env` on `app`, `apps/api/.env` on `numa`, `apps/api/.env` on `db`) and all four were already byte-identical, still holding the key session-021 set (`re_d9SE...`). Resend was rejecting that key outright, meaning it was revoked/rotated on Resend's side sometime after session-021, independent of anything in session-022's redeploy (which never touched `apps/web/.env`, only appended to `apps/api/.env` on numa/db).

User supplied a fresh key (`re_cYRwZuGL...`) directly.

## Notes / follow-ups

- **Second Resend rotation incident in 2 days.** Session-021's "no central secret store — repeat this same 4-file sweep if it rotates again" follow-up is now proven necessary twice. Worth asking whoever manages the Resend account to either stop rotating it ad hoc or set up a heads-up before doing so, since there's no monitoring that catches this before a user hits a broken login.
- Consider a lightweight canary (a scheduled `POST /api/auth/sign-in/magic-link` + check for `{"status":true}`, similar in spirit to the existing download canary) so a bad key is caught before a real user reports it.
- Fleet-wide sweep is still manual, 4 files across 3 servers. Same follow-up as session-021 stands: no central secret store yet.
