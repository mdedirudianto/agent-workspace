## Summary

Session-026 root-caused and documented (in this workspace, then properly relocated to the ytgrab repo's `docs/` per user correction) a bug where the per-tier Kuma canary's `urlenc()` silently dropped any push containing a non-ASCII byte — specifically the residential tier's `QUOTA_EXHAUSTED ... — plan out of bandwidth` message (em-dash) — causing 3 days of invisible residential outage plus the bulk of the Telegram noise the user reported. The dev-side fix landed on `fix/canary-push-encoding`, merged to `main` as `a1231c5` (`apps/api` 1.13.1), with 8 regression tests, `push()` now failing loudly on non-200, and two operator docs: `docs/CANARY_ALERTING_BUG.md` and `docs/CANARY_REDEPLOY_HANDOFF.md`.

This session executed the handoff's operator items 1 and 2, and additionally synced `db` and `app`'s repo checkouts to the same commit (user request, beyond the handoff doc's explicit scope) since both had drifted and this closes that gap cheaply while already in the fleet.
