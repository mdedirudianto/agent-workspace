## 2. nginx change on `proxy` (youtubegrab.com vhost only)

- `set_real_ip_from` for the 22 Cloudflare ranges (fetched live) + `real_ip_header CF-Connecting-IP`, so logs and limit keys now carry real client IPs.
- `geo $realip_remote_addr $ytgrab_via_cf`: `/api/*` from anything other than Cloudflare or `10.0.0.0/24` → **403**. This closes origin bypass and makes the `cf-*` headers trustworthy.
- `map $http_user_agent $ytgrab_bad_ua` (anchored regex for the exact `Chrome/128.0.0.0` UA) → **403** on `/api/*`. A regex rather than a plain string, so no global `map_hash_bucket_size` change was needed on this shared box.
- New `location ~ ^/api/v1/videos/[^/]+/download$`, carrying its own guards (a regex location wins over the `/api/` prefix): `limit_conn ytgrab_dl 6`, `limit_conn_status 429`, **`limit_conn_dry_run on`**, and the same proxy settings as `/api/`.
- Verification:
  - Bad UA → 403 on status and download.
  - Normal UA → 200 status, 206 download, merged download streams.
  - `--resolve` origin bypass → 403.
  - Web and 2 other vhosts → 200.
  - 403 breakdown after an hour: all scraper UA, plus 2 of my own bypass tests.
- Pre-existing `protocol options redefined` warnings from other vhosts are unrelated.
- Dry-run cap hits so far: **0**.

## 3. What shipped (repo `main` `b6ef8cc`, docs follow-up `dab4995`)

- **api 1.18.0:**
  - Gate timeouts, client aborts and 429s are no longer charged to proxy health on the download, merge, direct or player-client-chain paths.
  - A gate timeout is a 503 with `Retry-After`; an aborted resolve is recorded as `aborted`.
  - Latching **mass-disable breaker** (`PROXY_MASS_DISABLE_RATIO=0.2`, `PROXY_MASS_DISABLE_MIN=3`, defaults, no env change): soft faults only, only while the kind is still serving, never-revivable rows excluded. Pages `proxy_mass_disable_held`.
  - A nested undici 407 is graded hard.
  - `/status` `load` includes the yt-dlp gate.
- **web 1.15.4:** admin proxies table paginated (25/50/100); archived rows excluded from All.
- **canary:** `resolve_api` reads `HOST`/`PORT` via Node `util.parseEnv` (same parser as `--env-file`); `YTGRAB_API` overrides; the DOWN log line names the address tried.

## 5. Incident: web client assets 400 (14:40–15:29 WIB)

**Cause.** The deploy ran `pnpm --filter @ytgrab/web... build` in the foreground over SSH. The tool call hit its 10-minute timeout and was moved to the background, and `next build` then blocked on a dead stdout socket (`State: S`, 4.5 min CPU in ~40 min). `next build` deletes `.next/standalone` when it starts, so the running server had no client assets.

**Impact.** 31 `/_next/static/*` requests from 4 visitor IPs got 400. Pages rendered as HTML but didn't hydrate. The API, extension and mobile were unaffected.

**Fix.** Killed the build, rebuilt with `nohup … < /dev/null` into a log, restarted, smoke test OK. Runbook `docs/DEPLOYMENT.md` §6 now does exactly that.

**Lesson.** Never run a web build tied to an interactive or tool session. Run the asset smoke test *after* restart and before calling a web deploy done. I restarted the API and moved on without that check at 14:40, and nothing caught it until 15:22.
