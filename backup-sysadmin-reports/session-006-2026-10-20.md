# Session 6 — Fleet power-off 2026-10-19: post-restart audit, interrupted backup cycle, hygiene

**Date:** 2026-10-20
**Scope:** fleet-wide read-only audit of all 8 hosts (`app`, `db`, `proxy`, `erp`, `monitor`, `backup`, `dev`, `numa`). Write steps ran on `backup` (the reason this report lives here), plus small hygiene changes on `app`, `dev`, `db`, `proxy`, `monitor`.
**Server (primary):** `root@backup` (public `194.233.81.93`, internal `10.0.0.4`)
**OS:** Ubuntu 22.04.5 LTS
**Trigger:** the user noticed all servers had restarted overnight and asked for an analysis, a plan, then approval per step.

---

## Summary

All 8 hosts did a **graceful, externally triggered power-off** on 2026-10-19 between ~18:12 and 18:53 WIB and were powered back on 9–32 minutes later (user confirmed the provider triggered it). No local actor was found on any host: no sudo, cron, apt or unattended-upgrades activity before the shutdown, and `systemd-logind` / `systemd-shutdown` show a normal poweroff. app, proxy, erp, backup and numa came back on newer kernels. **Every service returned**: PM2 (app 48/48 online, dev 22 online / 35 stopped = baseline), Docker (monitor 9/9, dev as before), Postgres, Redis, MariaDB, Mongo, ClickHouse, erp supervisor 9/9, nginx on proxy with 55/55 private upstreams reachable, and 82 of 94 public domains answering 2xx (the other 12 are expected, see Verification).

Two things were **not** self-healing and were fixed here: (1) the 10-19 18:00 backup cycle was killed mid-`pg_dump` by the shutdown, leaving a truncated wagrab dump and skipping the tier-2/tier-3/mongo/erp-bench jobs for 10-19; (2) numa's PM2 was empty for ~14.5 h (handled in numa session-004, 09:33 WIB). The missed backup jobs were re-run by hand on 10-20 (all rc=0), the partial dump quarantined, and a set of long-failing `systemd --failed` units cleaned up.

## Incidents

- **Secret exposure (low):** `crontab -l` on numa was printed during the audit and contains the Kuma push-monitor URLs `KUMA_PUSH_DIRECT`, `KUMA_PUSH_DATACENTER`, `KUMA_PUSH_RESIDENTIAL` (the token is the URL path). Values are in the session transcript only and are not recorded here. They are write-only heartbeat endpoints; regenerate in Kuma if the transcript is shared.
- **Redaction:** `ops-redact` replaced one value in the `erp-bench.sh` listing (the `SSH_KEY=` line, almost certainly a key file path). Original not seen by the operator; script untouched.
- **Outage:** the provider power-off itself, see Window. Backup data impact: the 10-19 wagrab dump was lost; 10-14…10-18 dumps are intact, so wagrab's restore point was 10-18 19:09 until tonight's 18:00 run.
- **Process slip:** an exploratory `grep -rn` over `/home` and `/opt` on dev hung the shell for ~2 min (read-only, no impact). Re-run with a narrow scope.
