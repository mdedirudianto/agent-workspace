## Findings

1. **Retention never runs while a `(sd-pam)` process lives.** `!! retention skipped: the cwd of pid 2979804 (this user) could not be read (EACCES)`. Pid 2979804 is `(sd-pam)` (systemd's PAM helper for the `devops` user manager, started 2026-10-13); its cwd is unreadable by design. Harmless this time (3 releases, keep 4), but every deploy will skip retention until it is fixed, so releases accumulate (~1 build per deploy). Filed as grobiz D130.
2. **`59aba5d4` no longer matches the runbook:** its tax is **off** (`enabled:false`, PPN 11 configured) and it lists **0 products**, so the PPN case ran on `2caaaf0a` (PPN on, 30 items) and the tax-off case was simulated. Next runbook should name `2caaaf0a` for PPN.
3. **Runbook check 4 needs empty caches.** Blocking `/api/settings/taxes` and reloading still showed `Rp 27.750`: a cached tax read (the persisted query cache / SW `api-cache-v2`) counts as read, by design. With both cleared the till failed closed as specified.
4. **The runbook's "no gateway restart" was wrong.** `deploy.sh` restarts the gateway whenever `packages/shared` changes (`GATEWAY_PATHS`), though the gateway imports only `classifyJid`/`isCapturedVerdict`. Owner accepted; the one paired instance reconnected (`1 of 7 connected, 1 before`). Filed as grobiz D131 (narrow the rule, or have runbooks predict it).
5. Not a defect: `curl /pos` answers `404` JSON — the SPA fallback serves only `Accept: text/html` navigations (with that header: 200 `text/html`).
