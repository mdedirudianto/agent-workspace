## Result

**Admin and partner sign-in are now rate-limited at the edge, per real client IP.** `app.`, `api.` and `admin.gro.biz.id` restore the client IP from `CF-Connecting-IP` (Cloudflare ranges only) and send every `/api/admin/auth/*` and `/api/partner/auth/*` request through a new zone `grobiz_staff_auth`: 5 r/m, burst 5, CORS preflights uncounted. The 7th request in a row gets a JSON 429 in the API limiters' shape (`code`, `retryAfter: 12`, CORS for `https://partner.gro.biz.id`). The routine routes (`/api/admin/auth/{me,refresh,logout}`, `/api/partner/auth/{refresh,logout,register/status}`) are exempt, as before.

- **The brief's premise was wrong (DEC-2):** the live proxy had **no** `limit_req` for grobiz (the repo's `api_auth`/`api_general` zones live only in `deployment/nginx/`, which prod does not run) and **no real-IP restore**. Without the restore, `$binary_remote_addr` is a Cloudflare edge, so a limit would have been one bucket for every user (a global lockout). Both were added.
- **F3 is unchanged:** the vhost still forwards `X-Forwarded-For` with `$proxy_add_x_forwarded_for`, so Fastify's `request.ip` (`trustProxy: true`) is still the spoofable leftmost entry. The edge limit keys on the restored IP, which a client cannot spoof. The XFF overwrite is its own step (FU-6).
- Rollback: `cp -a /etc/nginx/sites-available/grobiz.gro.biz.id.conf.bak-20261019-staffauth /etc/nginx/sites-available/grobiz.gro.biz.id.conf && rm /etc/nginx/conf.d/grobiz-staff-auth.conf /etc/nginx/snippets/grobiz-cloudflare-realip.conf /etc/nginx/snippets/grobiz-staff-auth-locations.conf && nginx -t && systemctl reload nginx`.

## Findings

- The partner portal is cross-origin with no cookies, so the edge 429 needs `Access-Control-Allow-Origin`; without it the browser reports a network error. The origin is an exact-match map, never echoed.
- One bucket per client IP covers admin and partner sign-in together: three admins signing in from one office NAT inside ~12 s use it up, and the fourth gets a 429. Expected, not an attack (state B-4).
- Fastify's `useSemicolonDelimiter` must stay off while these regex locations are live (`login;…/me` would match the exempt pattern).
