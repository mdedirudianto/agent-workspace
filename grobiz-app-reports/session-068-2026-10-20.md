## Why

The six proxy locations that reach the API (`10.0.0.5:4000`) forwarded `X-Forwarded-For` with `$proxy_add_x_forwarded_for`. That appends to whatever the client sent. The API (`trustProxy: true`) took the left-most entry as `request.ip`, so any client could name its own address. That address feeds:
- every per-IP limiter;
- the admin IP allowlist;
- the callback failure counters;
- the audit rows.

**Baseline, 09:31 WIB, before the write:**
- Request: `curl -H 'X-Forwarded-For: 203.0.113.77' https://api.gro.biz.id/health?b001=b001base1792463468` → 200.
- `app:/home/devops/grobiz/logs/api-out.log` recorded `"remoteAddress":"203.0.113.77"`. The Mac's address is `157.85.212.99`.

## Change

`$proxy_add_x_forwarded_for` → `$remote_addr` in the six API locations:
- app `location /`
- api `location /`
- admin `location /api/`
- admin `location = /health`
- the two regex locations in the staff-auth snippet

`$remote_addr` is the client that `snippets/grobiz-cloudflare-realip.conf` restored from Cloudflare (included in all three vhosts). The landing server and the admin static `location /` (→ 7016) are unchanged.
