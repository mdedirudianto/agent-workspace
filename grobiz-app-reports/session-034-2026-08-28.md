## 1. Pre-flight — consolidated 23 runbooks into one plan, ground-truthed against the live server

Read every runbook and paired `docs/ops/` follow-up dated 2026-08-25 through 2026-08-28 (in addition to the
2026-08-25 catch-up runbook itself), resolved four places where reading them in file order alone would have
been redundant or incomplete (`backfill:shop-fields` is invoked by name in five separate runbooks for
different fields — it only needs to run once, verified against all 11 fields at once; the three POS-till
runbooks stack into a single API-before-web ordering window, not three separate ones; the kitchen-repair
runbook's verification sweep supersedes the older online-shop guide's version). Ground-truthed every claim
against the live server before trusting it: confirmed live SHA (`b277abb6`), confirmed all ten new env vars
absent, confirmed `/var/lib/grobiz/wa-sessions` did not exist, confirmed the exact 15-file migration set on
disk matched every runbook's citations, confirmed `DATA_MIGRATIONS` was unchanged since `0028`, confirmed
none of the 8 new tables existed in Postgres yet (clean slate for `db:push`), confirmed the wa-gateway
ecosystem block existed on `main`'s checkout with the correct `fork`/1-instance/`env_file` shape.

**One real gap found that no runbook flagged:** the online-shop feature's `deployment/nginx/conf.d/shop.conf`
uses a regex `server_name` on the documented assumption that "literal names beat regex, order doesn't matter."
That's true in general, but this cluster's `proxy` already has `server_name *.gro.biz.id` in `gro.biz.id.conf`
— a true nginx **wildcard** name (not a literal), routing every unmatched subdomain to ERPNext for per-tenant
site resolution. Nginx's real precedence is *exact → wildcard → regex*, so the wildcard always wins over
`shop.conf`'s regex, regardless of file order — merchant storefronts would have silently fallen into the
ERPNext wildcard and never reached the shop app. **Decision: ship the online-shop code (harmless dark —
additive migration, additive ERPNext fields) but leave `SHOP_BASE_DOMAIN` unset**, deferring the public launch
until the routing conflict is actually redesigned (a `map`-driven lookup inside the existing wildcard block,
or a second-level zone with its own cert). See follow-ups.

## 2. Decisions made with the user before executing

- **Map tiles: user supplied a MapTiler API key.** Set `MAP_TILE_URL`/`MAP_TILE_ATTRIBUTION` to MapTiler's
  raster XYZ endpoint (`https://api.maptiler.com/maps/streets-v2/{z}/{x}/{y}.png?key=…`) — this is the var the

  would produce zero address labels (same "show coordinates instead" degrade as leaving it unset) while adding
  no value. Flagged as a follow-up needing a Geoapify-shaped key.

### Bugs fixed
- **Loyalty redemption phantom cash change** (the headline fix — see §6).
- **`amount_paid` computed wrong on any redeemed sale** (previously derived as `grand_total − outstanding`,
  silently wrong since `grand_total` stays gross of a redemption).
- **Kitchen board 400 incident (2026-08-26)** — root cause was `backfill:shop-fields` having been run
  inconsistently across branches; script fixed (proper site-probing) and a degrade-instead-of-die fallback
  added.
- **Service-mode answer silently discarded** on open-order and QRIS-draft paths before the API ever saw it.
- **Item-edit on an online order** recomputing total blind to the baked-in promo.
- **Dynamic QRIS from the WhatsApp rail** minting a duplicate draft invoice.
- **ERPNext `Pricing Rule` silently discounting a bill the till never quoted** — every POS draft now writes
  `ignore_pricing_rule: 1` (deliberate behavior change — a merchant with a native ERPNext discount rule will
  see it stop applying; the supported replacement is a GroBiz promo).
- **Extension revenue badge had no permission gate** — `GET /api/sales/today` was readable by any
  authenticated user including a kasir; now gated behind `reports:read`.
- **F&B low-stock alert noise** — was flagging menu items that sit at 0 stock by design (produced via
  Manufacture chain post-sale); now filtered correctly.
