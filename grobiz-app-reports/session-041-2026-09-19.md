### 5.3 Webhooks — the stub, and what it proves

Prod is **mock-hard-off** (`MIDTRANS_MOCK`, `WA_GATEWAY_MOCK`, every `/simulate/*`), and the repo's
Xendit simulator refuses a production key by design. **Both money webhooks re-fetch the charge from
Xendit before acting** (`routes/webhooks/xendit.ts`: "asking Xendit's own API … is the
authentication"), so a stub cannot settle anything — which makes the stub a *security* test:

| Probe | Result |
|---|---|
| `POST /api/webhooks/xendit` no token / wrong token | **401** `Invalid callback token` (both) |
| valid token, unknown `external_id` | 200 `unknown` — no-op |
| valid token, **forged `PAID` against the real canary invoice**, no gateway id | 200 `ignored` — log: `PAID with no invoice id to verify` |
| valid token, **forged `PAID` + fake `smoke_fake_inv_041` id** | **500 fail-closed** — log: `re-fetch failed` → `Verification failed`. Invoice stayed `unpaid`, `paid_at NULL` |
| `POST /api/webhooks/xendit/qris` no token / unknown reference | **401** / 200 no-op |
| `POST /api/webhooks/xendit/disbursement` no token / unknown batch | **401** / 200 no-op |
| `POST /api/webhooks/midtrans` bad signature | **403** `Invalid signature` |
| `POST /api/webhooks/whatsapp` bad `X-Hub-Signature-256` | **401** |

Side-effect diff across the whole webhook run: subscription still `free`, **0** new
