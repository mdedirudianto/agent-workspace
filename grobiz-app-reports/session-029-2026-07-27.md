## Three production defects

1. **Admin suspend/unsuspend/plan-change don't take effect for up to 15 min — P2, reproduced live.**
   `plugins/tenant.ts` reads `tenant:<id>:config` (TTL 900 s), the only tenant key anything writes.
   `changeTenantStatus`, `overrideTenantPlan`, subscription-ops and `tenant-service` invalidate
   `tenant:<id>` and `tenant:<id>:subscription`, which are never written. Proven on production: deleting
   exactly what the code deletes reported **0 keys deleted** and the `active` tenant still got 403;
   deleting `:config` returned 1 and the same request returned 200. A **manual** admin unsuspend leaves a
   merchant locked out another 15 minutes. `registry.invalidate()` already exists and has no callers.
2. **Suspension split-brain — P2 latent.** The API enforces on `tenants.status`; the web's full-screen
   lock reads `subscriptions.status`. Root-causes the dev pass's deferred "unidentified overlay" (F5).
3. **Unencrypted second factor — P2/P3.** `admin_users.totp_secret` is plain base32 — this session minted
   the super-admin's codes from a DB read, which is what made the admin phase possible.
   `tenants.erpnext_api_secret` is unencrypted the same way.
