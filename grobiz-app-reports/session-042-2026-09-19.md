## 3. The 502 that was not a fault

The health check 6 s after `pm2 restart` returned **502 Bad Gateway**, and the newest log lines still
carried the OLD pid — which reads exactly like a failed boot. It was not:

```
21:40:52  GlitchTip error tracking initialized
21:40:54  Serving static files from: /home/deploy/grobiz/apps/web/dist
21:40:54  Server listening at http://127.0.0.1:7006
```

**The dev API takes ~50 s to bind `:7006`** (GlitchTip init, then static discovery), and nginx answers
502 for the whole window. Diagnosed by checking the port, the pid's sockets and the raw log tail rather
than by retrying the URL. Worth knowing before someone rolls back a healthy deploy on a 502.

## 4. `pnpm seed:defaults` is broken on dev — pre-existing, PG14-only

```
insert into "feature_flags" … on conflict ("key","scope","scope_value") do nothing
  → 42P10: there is no unique or exclusion constraint matching the ON CONFLICT specification
```

**Cause, and it is not this release.** `seed-defaults.ts` targets the conflict by *column list*, which
needs a unique index on exactly `(key, scope, scope_value)`. Prod's PostgreSQL 16 has that index from
`0007`'s `NULLS NOT DISTINCT`. Dev cannot: `NULLS NOT DISTINCT` is PG15+, so session-037 (`a1046557e`,
2026-09-02) emulated it as an **expression** index —
`UNIQUE (key, scope, COALESCE(scope_value, ''))` — which `ON CONFLICT (cols)` can never match.

- `seed-defaults.ts` has **0 lines of diff** in this range; its `onConflictDoNothing` dates to
  `a597bef8e` (2026-06-05). The incompatibility has existed on dev since **2026-09-02**.
- **Not a blocker here:** it aborts at `feature_flags`, and all 6 flags already exist on dev. The
  CR-015 config it was supposed to precede is written by the fee-schedule migration itself —
  `platform_config.platform_fee_schedule` landed correctly.
- **What it DOES skip on dev:** `platform_config`, `notification_templates`, `alert_rules`. Dev carries
  **8 alert rules against prod's 14**, which is likely this defect accumulating.
