# Session 1 — Initial production deploy: v4.maxchat.id

**Date:** 2026-09-02

## Context

`max` (product name "Maxchat v4", repo `github.com/biji-dev/max`) is a new pnpm/turbo monorepo, not previously deployed. Single deployable app: `apps/landing`, an Astro 7 + React 19 static site (`output: 'static'`, no adapter). No backend, no database. The waitlist form validates client-side and hands off to a WhatsApp deep link (`wa.me/6281234511449`); it optionally POSTs to `PUBLIC_WAITLIST_ENDPOINT` first, which is unset in this deploy (falls back to a local no-op stub).

DNS: `v4.maxchat.id` initially resolved to `dev` (`154.26.130.96`) — a stray/placeholder record, nothing served it there. `maxchat.id` is on Cloudflare nameservers but the record was DNS-only (grey cloud). User repointed the A record to `proxy` (`46.250.234.153`) mid-session; propagation completed within the session (~45 min).

## Decisions

- **Build on `app`, serve static from `proxy`** — matches the fleet convention (meetgrab web, eventopia web-public, seenow SPAs) rather than the repo README's own suggestion (Cloudflare Workers / Vercel).
- **Grey-cloud DNS (direct A record), not CF orange-cloud** — user's choice when repointing; simpler, HTTP-01 cert, no Cloudflare API token needed. Unlike meetgrab/eventopia/seenow/hoteru, this domain has no `cloudflare-*.ini` token on `proxy` — if orange-cloud + Full-strict is wanted later (CDN/WAF for the public landing page), a new scoped token needs to be created and DNS-01 reissuance done.
- New app-scoped report directory `maxchat-app-reports/` (not `max-app-reports/`) — matches the product name / domain, distinct from the older unrelated `~/Projects/maxchat/` ecosystem mentioned in `projects-reports/`.

## Redeploy recipe (for next session)

```bash
ssh devops@app "cd ~/max && git pull && pnpm install && pnpm build"
ssh devops@app "tar czf - -C ~/max/apps/landing/dist ." | ssh root@proxy "tar xzf - -C /var/www/v4.maxchat.id && chown -R www-data:www-data /var/www/v4.maxchat.id"
```

No nginx/cert changes needed for a routine content redeploy.

## Open follow-ups
